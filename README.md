# 清单

单人使用的任务、日程、SOP 与文档管理系统。React 前端、Express 后端，SQLite 保存数据，默认北京时间。

## 功能

- 任务与清单：项目、标签、筛选、分组、字段配置、排序、填色、批量操作、卡片批阅与统计。
- 日程：任务时间联动、普通日程、重复规则、多日历展示。
- SOP：主题、独立重复事件、触发规则、执行记录、未来发生与工作日历维护。
- 文档：层级目录、Markdown、搜索、版本记录与回收站。
- 设置：外观、字体、导航、清单显示及本机使用统计。

不包含 AI、邮件系统、节点系统、飞书机器人及同步、外部推送、Webhook、CLI 授权或原部署环境。该仓库使用全新提交历史，不是生产数据库备份。

首次启动只建立空白数据库、通用清单与默认设置，没有真实任务、日程、文档、聊天、账号或凭据。不要将生产数据库直接放入这个版本。

## 本机运行

需要 Node.js 22.18 或更新版本、npm。数据库使用 Node 内置 SQLite。

1. 将 `.env.example` 复制为本机 `.env`。
2. 填写 `ADMIN_PASSWORD`，至少 12 位；没有默认密码。用户名默认为 `admin`。
3. 执行：

```sh
npm ci
npm run build
npm start
```

打开 [本机清单](http://127.0.0.1:3000)。数据默认保存在 `data/`，刷新或重启不会清空。

开发时分别运行 `npm run dev:server` 和 `npm run dev`；前端在 `127.0.0.1:5173`，将 `/api` 代理到本机 `3000`。修改后端端口时同时修改 Vite 代理。

## Docker

准备好 `.env` 后执行：

```sh
docker compose up -d --build
```

默认只绑定本机回环地址，数据位于 `task-data` 卷。远程访问应自行配置受保护的反向代理和 HTTPS。启用 HTTPS 后将 `COOKIE_SECURE=true`，`TRUST_PROXY_HOPS` 必须与实际可信代理层数匹配。

## 验证与数据安全

```sh
npm test
npm run build
```

测试使用临时数据库和临时生成的密码，不访问生产服务。不要提交 `.env`、数据库、附件、备份、会话、日志及包含个人数据的截图。`.gitignore` 是辅助保护，不替代提交内容检查。

备份时先停止本实例再复制完整数据目录；不要在运行中只复制 SQLite 主文件而遗漏 WAL。不要把应用服务直接暴露到不可信网络。本版本面向个人部署，不提供多人权限体系。

使用统计仅保存在本实例数据库，没有远程遥测。应用不会连接原系统、发送邮件或触发机器人。
